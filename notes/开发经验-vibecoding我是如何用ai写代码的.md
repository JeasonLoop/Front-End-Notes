# Vibe Coding：我是如何用 AI 写代码的

最近 Vibe Coding 这个词挺火的，其实我已经这么干快一年了，分享一下我的工作流。

## 什么是 Vibe Coding

简单说就是：**你把你的感觉、你的大概想法告诉 AI，AI 帮你把代码写出来**。不需要你抠每一个 API，不需要你写清楚每一步逻辑，你把「vibe」（感觉/氛围）传递对了，代码就出来了。

## 我的 Vibe Coding 工作流

### 第一步：讲清楚上下文

```
我现在在写一个 React 项目的自定义 Hook，需求是监听窗口大小变化，返回当前宽度，需要做防抖，默认 200ms，允许自定义。
用 TypeScript，要加类型注释。
```

一定要告诉 AI：
- 你用的什么技术栈（React/Vue/Node 什么版本）
- 大致需求是什么
- 有什么特殊要求（类型、错误处理、性能）

### 第二步：让它写，然后你改

AI 写完，你跑一下，能用就收下，不能用就把错误扔回去，说「这里报错了，帮我看看是什么问题」。

如果效果不对，你就说：「我想要的不是这样，应该是 xxx」，再调一轮，大部分时候两轮就能搞定。

### 第三步：重构优化

能用了之后，你再自己过一遍代码，看看哪里可以优化，哪里不太对，或者直接让 AI 帮你优化：「帮我把这个函数重构一下，拆分一下，可读性更好一点」。

## 哪些场景适合 Vibe Coding

✅ **非常适合**：
- 工具函数、通用 Hook
- 正则表达式写不对，让 AI 写
- 复杂 CSS 效果，你描述要什么感觉，让它调
- 写单元测试
- 写文档、写注释

❌ **不太适合**：
- 核心业务逻辑（你得自己想清楚）
- 性能要求极高的核心路径（AI 可能会写废话）
- 安全性要求高的代码（还是自己审一遍）

## 我踩过的坑

1. **AI 会发明不存在的 API**——特别是一些比较新的库，它有时候会瞎编参数，你跑一遍就知道了，改改就好。

2. **需求说不清楚，结果肯定不对**——你自己都没想明白，AI 怎么可能写对。先想清楚，再让 AI 帮你敲代码。

3. **不要让 AI 帮你 debug 你自己都看不懂的问题**——你得告诉它报错信息、上下文、你已经试过什么方法，不然它瞎猜。

## 最后

Vibe Coding 不是「甩手掌柜coding」，它是**把重复劳动交给 AI，你把精力放在需求理解和架构设计上**。

编码几十年，从最开始的手写汇编，到现在 AI 帮你写代码，工具越来越先进，核心其实没变：**解决问题才是关键**，代码只是工具。
