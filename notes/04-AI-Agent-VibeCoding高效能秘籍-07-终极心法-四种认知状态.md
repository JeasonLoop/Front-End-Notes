# 终极心法：四种认知状态

> 对应课程终章。全书所有方法论背后贯穿的一条暗线。

开篇那个场景回看：Agent 写完文件上传接口说"实现已完成，可以直接使用"，多问一句"有什么安全风险"，它自己列出四个都能出事故的问题。那一刻：

- Agent：不知道漏洞存在，**也不知道自己不知道**——所以语气笃定。
- 作者：不知道有没有漏洞，但**知道自己不知道**——所以多问了那一句。

解决交付风险的不是高级技巧，是认知状态的差别：一个"不知道自己不知道"的系统，碰上一个"知道自己不知道"的人，事故就没有发生。

## 四种状态对照表

| 状态 | 典型翻车 | 对应方法论 |
| --- | --- | --- |
| 知道自己知道 | **知识的诅咒**：你熟到意识不到"它的来历"是一条需要交代的信息 | prompt 四件套、CLAUDE.md、decisions.md——把你知道的搬到 Agent 面前 |
| 知道自己不知道 | 方案没想清硬撑着派活；轻信"实现已完成" | 摸底、grill 拷问、讨论先行；默认产出可能有错 → 独立 review、验收闭环 |
| 不知道自己知道 | 隐性知识（品味、判断、踩坑经验）没被挖掘 | grill 逼问、错题本、对比训练——**你的护城河埋在这一层** |
| 不知道自己不知道 | 面板被盖住（代码全对但 UI 是挂的）、状态存本地内存（本地不复现）、流水线静默失败 | **引入外部视角**（独立 review、换模型、隔离评估、"你漏掉了什么"、给 Agent 接浏览器）+ **机器验证**（typecheck/测试/hooks/回归用例/验证器告警） |

要点：

- 第四层靠自己反思解决不了——你不可能"想起来"你没想到的东西，只能靠外部视角和机器机制。
- 第三层是价值变现的关键：AI 把公共知识的价值抹平了（文档里有的、教程里讲的人人都能引出来），拉开差距的是隐性知识。把"不知道自己知道"挖出来变成"知道自己知道"的资产，就是个人价值变现的过程。
- 更简单的规律：知识只有两种存在状态——**明处**（写下来的：prompt 约束、CLAUDE.md、checklist、Skill）和**暗处**（其余全部）。全书方法论方向始终只有一个：**把知识从暗处搬到明处，并且不让它退回去。**暗处的知识只能自己用一次，明处的可复用、不过期——这就是复利。

## 最后：怀疑这件事，只能你来做

论知识量、输出速度、体力，Agent 都比你强，但它有个等模型升级也等不来的天生短板：**它不会怀疑自己**。你自己写完代码心里会不踏实，它没有——永远觉得干得挺好。

一路搭的那些东西全是"怀疑"的具体形态：验证闭环是把"心里不踏实"变成自动跑的检查；独立 review 是把"找人再看一眼"固定成流程；验证器是把怀疑接进自动化流水线。但哪里该设检查、检查到什么程度才算放心——这个念头只能从你脑子里冒出来。

未知永远清不空，但可以管理：让发现问题的渠道一直开着（测试、review、告警），每撞见新的未知就沉淀一条规则。

**方法论会过时，模型会换代，工具会淘汰，但一个清楚自己知道什么、也清楚自己不知道什么的人，放到任何时代、配上任何工具，都有稀缺价值。**
