# 中高阶前端必懂：闭包其实并不难

闭包这个词，刚学 JS 的时候觉得好玄乎，面试也经常问，工作几年回头看，其实没那么复杂，整理一下我的理解。

## 一句话说清楚闭包

**函数能够访问外部函数作用域的变量，即使外部函数已经执行完了**——这就是闭包。

```javascript
function createCounter() {
  let count = 0;
  return function() {
    count++;
    return count;
  };
}

const counter = createCounter();
console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
```

`createCounter` 执行完了，按理说局部变量 `count` 应该被销毁了，但因为返回的匿名函数还引用着它，所以 `count` 活下来了，这就是闭包的魔力。

## 闭包产生的本质

本质原因就是**JS 的词法作用域** + **函数作为一等公民可以被返回/传递**。

JS 函数的作用域是定义的时候就确定了，不是执行的时候确定的。所以哪怕你把函数拿到别的地方执行，它还是记得它定义时周围有哪些变量。

## 日常开发中，闭包用在哪

### 1. 函数柯里化 / 参数复用

```javascript
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    } else {
      return function(...nextArgs) {
        return curried.apply(this, args.concat(nextArgs));
      };
    }
  };
}
```

每次传部分参数，返回一个新函数等着接收剩下的参数，这里就是靠闭包保存已经传进来的参数。

### 2. 模块化 / 私有变量

```javascript
const module = (function() {
  let privateVar = 0;
  function privateMethod() {
    // ...
  }
  return {
    publicMethod: function() {
      privateVar++;
      privateMethod();
    }
  };
})();
```

IIFE 立即执行函数，暴露出公共方法，私有变量只能被公共方法访问，这就是利用闭包实现模块化。现在 ESModule 普及了，但原理还是这个意思。

### 3. React Hooks

```javascript
function useCounter(initial = 0) {
  const [count, setCount] = useState(initial);
  function increment() {
    setCount(count + 1);
  }
  return { count, increment };
}
```

你看，每次组件渲染，`useCounter` 执行完了，`increment` 函数还能访问 `count` 和 `setCount`，这不就是闭包吗？

React Hooks 能用，本质就是闭包在支撑。理解了闭包，你就能理解为什么有时候 `useEffect` 拿到的是旧值了。

### 4. 防抖节流

```javascript
function debounce(fn, delay) {
  let timer = null;
  return function(...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => {
      fn.apply(this, args);
    }, delay);
  };
}
```

`timer` 变量存在闭包里，每次调用都能访问到上一次的定时器，完美。这是面试常考，也是实际开发天天用。

## 常见的坑：循环中的闭包

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 1000);
}
// 输出 3 3 3，不是 0 1 2
```

为什么？因为 `var i` 是函数作用域，三个 setTimeout 回调共享同一个 `i`，等定时器执行的时候，循环已经结束，`i` 已经是 3 了。

解决方法：
- 用 `let i` 代替 `var i`（let 块级作用域，每次循环都有新的 i）
- 用 IIFE 捕获当前 i
- 用 forEach 遍历

## 总结

闭包真不是什么玄乎的概念，就是 JS 词法作用域的自然结果。你天天写代码其实都在用，只是你可能没意识到。

理解了闭包，你看 React Hooks、柯里化、防抖节流这些概念，都会通透很多。
