# 需求规划与 UI 设计：SDD 与 Impeccable

> 对应课程第四章。决策是你的，执行交给 Agent——这条原则在规划（SDD）和设计（Impeccable）两个领域的落地。

## 1. SDD：用法不对就是定时炸弹

spec 回答"做什么"（目标、边界、交互规则、验收标准），plan 回答"怎么做"（执行步骤/tickets）。方向完全正确——SDD 整套流程就是冲着"一句话 prompt 缺目标、缺边界、缺验收标准"来的。

**炸弹埋在哪**：大部分人的用法是让 AI 在信息不充分时直接生成 spec = 让它替你拍板所有关键决策（方案选型、动哪些模块、接口设计）。错误决策从 spec 顺着 plan 传导，spec 成了 source of truth 后没有环节回头质疑，实施到一半才发现，纠错成本已经远高于讨论阶段。

Plan Mode 两种错误姿势：甩手掌柜型（plan 看着像样就确认，关键决策全是 AI 脑补的）；劳模型（巨长 prompt + 来回改 plan，最后"差不多行了"还是有坑）。

### 解药：讨论先行，把决策和规划分开

像盖房子：先跟建筑师讨论好布局材料，图纸确认了再开工，不让施工队一边画图纸一边砌砖。

1. **先摸底**："先别出方案。把相关代码读一遍，告诉我现在是怎么实现的？要加这个能力会牵扯哪些地方？"——理解偏差在这个阶段纠错成本几乎为零。（作者案例：Agent 以为进度数据在前端管理，实际源头在数据库，直接写 plan 会全盘走错方向。）
2. **抛出想法，主动邀请抬杠**："我倾向于 A，你觉得有什么问题？有没有我没想到的备选？不要顺着我说，先挑毛病。"
3. **逐个确认关键决策**：方案选型、数据存储、影响面、边界处理。**你没点过头的决策，就是 AI 自己拍的板。**讨论长就边聊边记 `decisions.md`（防 compact 丢失，也是收口核对清单）。
4. **全部敲定才写 plan**：review 重点从"方案对不对"变成"步骤有没有漏"。执行中发现决策要改：别在旧 plan 上缝补，回讨论重新敲定后直接重新生成 plan（生成只要几十秒）。

Plan Mode 本身没错（只读模式适合讨论阶段），错的是使用姿势。

## 2. SDD 工具：两个流派与裁剪判据

### Grill Me（Matt Pocock）：假设你已有方案

AI 反过来拷问你，一次一问、每问带推荐答案。核心提示词就几句话，最值钱的是：**"事实（代码里、环境里能查到的）你自己去查，不要来问我；但决策是我的，每一个都要摆到我面前，等我拍板。"**

grill-me（纯拷问）vs grill-with-docs（拷问 + 术语进 CONTEXT.md 词汇表 + 重大决策记 ADR）。ADR 的准入门槛（三条同时满足）：改起来伤筋动骨、不留背景看不懂、当时真的纠结过。

完整链条：`grill-with-docs → to-spec → to-tickets → implement(TDD) → code-review`。

### Superpowers：假设你只有模糊想法

brainstorming skill 像装修设计师：每步给 A/B/C 选项加推荐，你只做选择题；页面结构直接画交互式线框图让你点选。全程你只负责拍板。执行层可选 inline（主会话干）或 subagent-driven（隔离上下文 + 逐任务 review）。

它"重"（工序多、文档多、review 次数 = 任务数 + 1），但**本质是模块化 skills，可裁剪**。

### 裁剪判据：模型越强，流程越要轻

每道工序都在对冲"模型可能出错"的某个风险。用最前沿模型时很多偏差一次就能理解到位，工序成本却没变。审任何新工具都用这个问题：**它的每一道工序，对冲的是模型的哪个短板？这个短板在你用的模型上还存在吗？**

- 前沿模型：默认 grill-with-docs（价值密度最高的部分 + 轻）；Superpowers 借 brainstorming 骨架，执行换 executing-plans。
- 模型不够强 / 超大重构：该重就重，全套流程的冗余仍然值。

## 3. UI 质量：AI Slop 与 Impeccable

Slop 成因：不给约束时，AI 的每个设计决策都滑向训练数据里最高频、最"安全"的答案（紫蓝渐变、星星 icon、Inter 字体）。两层坑：第一层点名禁止就行；第二层你禁掉一个模板它换另一个模板——要躲开的是"从模板库里挑"这个行为本身。

**Impeccable**（`npx impeccable install`）覆盖起稿到迭代全流程：

| 步骤 | 命令 | 干什么 |
| --- | --- | --- |
| init | `/impeccable init` | 生成 PRODUCT.md（战略层：给谁做、品牌调性、**反面参考**——AI 最猜不到的信息）+ DESIGN.md（视觉层） |
| craft | `/impeccable craft 官网首页` | 多道强制关卡的起稿：访谈出 brief 等你确认 → 确认方向 → 确认配色 → 才写代码（讨论先行的设计版） |
| critique | `/impeccable critique 首页` | 两个互相隔离的评估（subagent 按 Nielsen 十项可用性启发式逐项打分 + 确定性脚本扫 Slop 模式），把"总觉得哪里不对"变成 P0/P1/P2 分级清单 |
| polish | `/impeccable polish 首页` | 直接读 critique 快照当待办，逐项修复 + 自验 |
| live | `/impeccable live` | 页面上点选元素生成三个变体原地对比，Accept 直接写回源码（解决"用语言描述审美太低效"） |

使用要领：

- 区分 register：设计即产品（官网/落地页）走 brand 敢于表达；设计为功能服务（后台/工具）走 product。
- craft 起稿别给太细的要求，给方向感，具体方案在关卡里挑。
- critique 的建议**不是全收**：设计取舍必须你来做；明确不认同的写进 `ignore.md`（错题本的反向版本——记"哪些'错'其实是我的品味"）。
- 一次只改一两个点，小步迭代。

## Checklist

- [ ] 复杂功能先摸底、再抬杠、逐个确认决策、最后才写 plan
- [ ] 没点过头的决策不进 plan
- [ ] 选 SDD 工具前问过"它对冲的短板在我用的模型上还存在吗"
- [ ] UI 项目有 PRODUCT.md / DESIGN.md，含反面参考
- [ ] critique 建议逐条筛过，不认同的进了 ignore.md
